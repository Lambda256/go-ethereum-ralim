# Maintaining this fork

`Lambda256/go-ethereum-ralim` carries a small patch set on top of upstream
`ethereum/go-ethereum`: configurable peer-to-peer bandwidth limits
(`--bandwidth.download` / `--bandwidth.upload`).

Nothing here is ever contributed back upstream. Pushes to
`ethereum/go-ethereum` are blocked by `.githooks/pre-push`, and the GitHub CLI
is pinned to this fork so `gh pr create` cannot target the parent repository.

## Branches

| Branch | Role |
| --- | --- |
| `master` | Untouched mirror of upstream. Advanced only by fast-forward. Commits are rejected by `.githooks/pre-commit`. |
| `ralim` | The patch stack, rebased onto an upstream **release tag**. Work here; open pull requests against this branch. |
| `feat/*` | Cut from `ralim`, merged back into `ralim`. |

`ralim` is based on a release tag rather than `master`'s tip, so the current
delta against upstream is:

```sh
git diff $(git describe --tags --abbrev=0 $(git merge-base master ralim))..ralim
```

The base tag is currently **v1.17.5**.

## One-time setup per clone

```sh
./.githooks/install.sh
```

The guards live in `.git/config` and `.git/hooks`, neither of which is
versioned, so a fresh clone has none of them until this runs. Re-run it after
editing anything under `.githooks/` — the hooks are copied into `.git/hooks`,
not symlinked. (`core.hooksPath` is deliberately not used: it resolves against
the working tree, so the hooks would vanish whenever `master` is checked out.)

## Syncing with upstream

`rebase_new_tag.sh` does the whole routine. Give it the new release tag:

```sh
./rebase_new_tag.sh v1.18.0          # rebase and verify, push nothing
./rebase_new_tag.sh v1.18.0 --push   # ...and publish when it passes
```

It fetches upstream, fast-forwards the `master` mirror, replays the patch
stack onto the tag, then runs `gofmt`, `go generate`, `go build` and the `p2p`
tests before letting you push.

The current base tag is not stored anywhere — the script recovers it with
`git merge-base ralim upstream/master`, which is exactly the commit the patch
stack forks off. Pass `--from <tag>` if that derivation ever fails (a tag cut
off a maintenance branch rather than master).

Other flags: `--no-verify` to skip the build and tests, `--no-mirror` to leave
`master` alone.

Every run writes a backup ref first, so any run can be undone:

```sh
git update-ref refs/heads/ralim refs/fork-backup/ralim-<timestamp>
git checkout -f ralim
```

To do it by hand instead:

```sh
git fetch upstream --tags
git checkout master && git merge --ff-only upstream/master && git push origin master
git checkout ralim && git rebase --onto v1.18.0 v1.17.5 ralim   # <new> <old>
gofmt -l p2p cmd && go build ./p2p/... ./cmd/... && go test ./p2p/
git push --force-with-lease origin ralim
```

Update the base tag recorded above whenever the base moves.

### Conflicts to expect

`p2p/config_toml.go` is generated by gencodec (see the `go:generate` line in
`p2p/config.go`). Never resolve a conflict there by hand — `rebase_new_tag.sh`
detects the case and regenerates the file for you. Manually:

```sh
git checkout --theirs p2p/config_toml.go
go generate ./p2p/
git add p2p/config_toml.go
```

The real conflict risk is `cmd/utils/flags.go` and `cmd/geth/main.go`, where
upstream frequently adds flags next to ours. Resolution is mechanical — keep
both sides. `p2p/bandwidth.go` is a new file and never conflicts, so keep new
logic there and keep the edits to upstream files down to single call sites.

### After a rebase

`ralim` is force-pushed, so anyone holding a feature branch must rebase:

```sh
git fetch origin
git rebase origin/ralim
```

`install.sh` sets `pull.rebase true` to make this the default.
